## 1. Bezpieczeństwo

### DEBUG=True w `.env` jako domyślna wartość ❌ → ✅ NAPRAWIONE

- **Problem**: Domyślna wartość `DEBUG=True` — jeśli `.env` nie zostanie edytowany, aplikacja startuje w trybie debug
- **Naprawa**: Zmieniono na `DEBUG=False`
- **Priorytet**: Krytyczny

### Hardkodowany `SECRET_KEY` w `testing.py` ⚠️ ZAAKCEPTOWANE

- **Plik**: `services/web/config/settings/testing.py:10`
- **Ocena**: Akceptowalne — klucz izolowany wyłącznie do środowiska testowego, nigdy nie trafia do prod
- **Priorytet**: Drobny

### Hardkodowany `FIELD_ENCRYPTION_KEY` w `testing.py` ⚠️ ZAAKCEPTOWANE

- **Plik**: `services/web/config/settings/testing.py:99`
- **Ocena**: Akceptowalne — środowisko testowe, nie prod. Ten sam klucz co w `.env.example`
- **Priorytet**: Drobny

### SQL Injection ✅ BRAK PROBLEMÓW

- Wszystkie zapytania przez Django ORM (QuerySet), zero surowych SQL

### Shell Injection w rsync ✅ ZABEZPIECZONE

- `shlex.quote()` zastosowane na `ssh_key`
- Parametry `CMD` jako lista (nie string) — subprocess bez shell=True

### XSS w szablonach ✅ BRAK PROBLEMÓW

- Wszystkie `{{ }}` — Django auto-escaping aktywny

### CSRF Protection ✅ BRAK PROBLEMÓW

- Wszystkie formularze POST mają `{% csrf_token %}`

### Szyfrowanie wrażliwych pól ✅ DOBRZE ZAIMPLEMENTOWANE

- `password` i `ssh_key` → `EncryptedCharField` / `EncryptedTextField` (Fernet AES-256)

## 2. Docker

### Brak `.dockerignore` ❌ → ✅ NAPRAWIONE

- **Problem**: Build context zawierał `__pycache__`, `.env`, `.git`, całe `docs/`
- **Naprawa**: Utworzono `.dockerignore` z wykluczeniami

### Brak healthchecks ❌ → ✅ NAPRAWIONE

- **Problem**: Redis, web, worker bez healthchecks — `depends_on: service_started` nie gwarantuje gotowości
- **Naprawa**: Dodano healthchecks, `depends_on` zmieniony na `service_healthy`

---

## 3. Django / Celery

### `celery.py` domyślnie ładuje settings `development` ❌ → ✅ NAPRAWIONE

- **Problem**: `os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'config.settings.development')`
- **Naprawa**: Zmieniono default na `config.settings.production`

### Brak `CELERY_BROKER_CONNECTION_RETRY_ON_STARTUP` ❌ → ✅ NAPRAWIONE

- **Naprawa**: Dodano `CELERY_BROKER_CONNECTION_RETRY_ON_STARTUP = True` w `base.py`
